OpenGHG Live Dashboard Architecture Options

Prototype flows for JASMIN-hosted model pipelines feeding an AWS Amplify dashboard.

Recommended Starting Point

Start with Option 1: JASMIN + OpenGHG post-processing + S3 artefact publishing + Amplify polling. It is the lowest-budget path and can evolve into the event-driven options later.

Option 1: Low-Budget S3 Polling

    subgraph JASMIN[JASMIN HPC Workspace]

Option 2: Event-Driven Push

flowchart LR
    subgraph JASMIN[JASMIN HPC Workspace]
        SCHED[Slurm/Cron/Cylc]
        MODELS[Model A/B/C\nOpenGHG-based pipelines]
        POST[OpenGHG output normaliser]
        PUB[Publisher\nwrites products + manifest]
        UPLOAD[Upload to S3]
    end
    subgraph AWS[AWS Serverless Backend]
        S3[(S3 run artefacts)]
        EVT[S3 Event Notification\nObjectCreated manifest.json]
        LAMBDA[Lambda ingest function\nvalidate manifest\nupdate index]
        DDB[(DynamoDB run index\nlatest, status, metadata)]
        APPSYNC[AppSync GraphQL\nsubscriptions/WebSocket]
    end
    subgraph AMPLIFY[AWS Amplify Dashboard]
        APP[Amplify hosted frontend]
        SUB[Subscribe to run updates]
        READ[Query run index\nfetch products from S3]
        UI[Live dashboard views]
    end
    SCHED --> MODELS --> POST --> PUB --> UPLOAD --> S3
    S3 --> EVT --> LAMBDA
    LAMBDA --> DDB
    LAMBDA --> APPSYNC
    APP --> SUB --> APPSYNC
    APP --> READ --> DDB
    READ --> S3
    SUB --> UI
    READ --> UI

Option 3: Queue-Backed Robust Ingestion

flowchart TB
    subgraph JASMIN[JASMIN HPC Workspace]
        SCHED[Orchestrator\ncron + sbatch\nor Cylc/Nextflow/Snakemake]
        M1[Model A]
        M2[Model B]
        M3[Model C]

        API[API Gateway or AppSync API]
    end
    subgraph DASH[Amplify Dashboard]
        FRONT[Frontend]
        STATUS[Run status panel]
        DATA[Fetch indexed metadata\nand S3 products]
    end
