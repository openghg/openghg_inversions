CO₂ model family#

The advanced CO₂ model family contains the CO₂-only and linked CO₂/O₂ recipes. O₂ is a tracer in the linked recipe, not a standalone supported model. Both recipes begin from scientific arrays that have already been prepared; they are not alternative species settings for the complete standard runner.

Current support#

Capability

CO₂-only

Linked CO₂/O₂

Intended use

One CO₂ channel with a correlated positive retained state and coherent aggregation covariance.

CO₂ and O₂ channels with shared and tracer-specific retained states and cross-channel covariance.

Public entry point

openghg_inversions.rhime.co2.run_co2() consumes a configured product request in Python or through model selection. Scientific likelihood choices select the matching inference implementation.

openghg_inversions.rhime.co2.run_rhime_co2_o2_from_prepared_inputs() and the matched fixed-OU run_rhime_co2_o2_cached_sigma_from_prepared_inputs(). A complete run_rhime_co2_o2 entry point is not available.

Acquisition and preparation

openghg_inversions.rhime.co2.prepare_co2_inputs() combines canonical RHIME observations and metadata with one coherent reduction in a dedicated Co2PreparedInputs artifact.

openghg_inversions.rhime.co2.prepare_co2_o2_inputs() gathers caller-supplied, channel-native prepared arrays; it does not acquire OpenGHG data. Save and replay linked prepared inputs describes NetCDF/Zarr persistence, including optional labelled independent errors.

Configuration

TOML selects the likelihood, priors and baseline choices for run_co2. Full and shared saved operations resolve their own applicable choices.

A packaged TOML template configures linked saved phases. The direct Python runners retain their separate configuration resolver.

Fixed-OU mismatch

Fixed tau and fixed or inferred site amplitudes. Inferred amplitudes automatically use the matched cached quadratic sampler.

Fixed tau and fixed or inferred amplitudes by species/site, preserving cross-channel aggregation covariance. The matched cached sampler updates all active affine coefficients. Requires the same channel units.

Boundary conditions and offsets

Model configuration can select prepared H_bc boundary sensitivity and add global, site, or site-by-period offsets.

Channel-labelled boundary sensitivities, priors and activity, plus independent global, site, or site-by-period offsets (same-unit channels).

Prediction

Native PyMC prior/posterior observation draws; fixed-OU recipes expose a joint log likelihood, including the matched cached-sigma recipe.

Native PyMC prior/posterior observation draws; fixed-OU recipes expose a joint log likelihood, preserving cross-channel covariance with the matched cached sampler.

Staged workflow

--model co2 phases consume one preparation or sample manifest for every supported likelihood, including inferred fixed OU.

--model co2_o2 phases consume one preparation or sample manifest for the same-unit joint model; see Staged linked CO₂/O₂ commands.

Outputs and postprocessing

Scientific operation composition retains an annotated xarray DataTree. Configured execution returns Co2Output with its trace, in-memory products and requested file paths. Conditional native-flux and country summaries are available from a bound affine artifact; staged basic, concentration, conditional native-flux and country products are available, with supported PARIS exports.

Direct runners return an annotated xarray DataTree. Saved replay returns Co2O2Output with channel components, predictions, residuals, shared state scaling and separate CO2/O2 products. Supported PARIS concentration and conditional bucket-native products are available.

Validation and acceptance

Coherent preparation, dedicated serialization, model construction, configuration resolution, replay, provenance, and cached-sampler behavior have automated regression tests, including installed CLI stage sequences. Scientist acceptance remains future work.

Preparation, graph construction, mixed-unit metadata, replay, and provenance have automated regression tests. Configuration currently limits linked replay to one shared concentration-unit label. Production scientist acceptance remains future work.

Prerequisites#

Readers should already understand labelled xarray state and observation dimensions, the distinction between native and retained state, and covariance in the observation likelihood. The shared pages on grouped basis layouts, native covariance, and coherent reduction provide that background without making those concepts specific to CO₂.

The family page records present software support, not evidence that a selected recipe is scientifically suitable for a particular inversion. Remaining scientist acceptance is tracked in OPE-79. The CO₂ commands reuse the TOML configuration boundary and prepared-input scientific operations.

The CO2-only handoff is intentionally separate from both the generic RhimePreparedInputs boundary and the linked CO2/O2 preparation contract. It does not add coherent-reduction or aggregation-error options to the standard and multisector runners or to run_hbmcmc.py.

Staged CO₂ commands#

CO₂ starts from canonical scientific inputs and a coherent reduction, or an existing Co2PreparedInputs artifact. It does not acquire OpenGHG data or infer a coherent reduction from a gas name. run_co2 prepares or loads inputs, explicitly materializes the selected scientific arrays, constructs the model, samples, then calculates and writes requested products. Full execution uses no manifests. Direct scientific callers can compose materialization, model construction, sampling and trace annotation explicitly; see CO₂ model recipes.

Saved phases call those same scientific operations. prepare references an existing numerical artifact and its optional affine companion in place; keep those files available for later operations. Python callers can also prepare from canonical inputs and a coherent reduction. A new prepared/affine pair is saved with the existing codecs and checked by the affine loader before its manifest is written. Imported pairs retain their numerical association. Both routes retain source labels, grids and projection meaning.

Record original requested dates and domain explicitly. Filtering can remove observations at both edges, so retained observation extrema cannot supply the original request. Missing imported facts fail clearly; supply prepared_inputs.start_date, end_date and domain, or retain those facts in preparation provenance. Sites and averaging periods come from the retained numerical preparation.

A TOML configuration can contain:

format_version = 1
recipe = "co2"

[prepared_inputs]
path = "prepared-co2.nc"
start_date = "2020-01-01"
end_date = "2020-02-01"
domain = "EUROPE"

[likelihood]
kind = "additive_sigma"
sigma_prior = { pdf = "halfnormal", sigma = 1.0 }

[sampling]
draws = 1000
tune = 1000
chains = 4
random_seed = 12345
sample_prior_predictive = 100
sample_posterior_predictive = true

[outputs]
output_format = "basic"
output_name = "co2"

Configured execution from prepared inputs writes the selected products:

rhime run --model co2 -c co2.toml --output-path run/full

To infer independent site amplitudes with fixed OU correlation, replace the likelihood table with:

[likelihood]
kind = "fixed_ou"
tau_hours = 24.0
site_amplitude_prior = { pdf = "gamma", alpha = 2.0, beta = 3.0 }

run_co2 selects the matched cached update automatically. Configure draw counts, tuning length, chains and seed in sampling; do not specify nuts_sampler. Additive sigma uses NumPyro; site sigma, scalar sigma and fixed-amplitude OU use PyMC. The inference policy table explains which choices are technical requirements and which are defaults. Inferred-OU tuning belongs to sampling.sigma_target_accept and sampling.state_target_accept. Saved Python sampling takes the same sampling mapping as the full configuration.

rhime run-co2 remains a transitional alias until its approved command-name retirement lands. This configured CLI route uses run_co2 and writes requested products. Python rhime.run(model="co2", config_file="co2.toml") selects the same configured runner and returns Co2Output. Acquisition and construction of the defining native-resolution reduction remain separate from this prepared-input route. That extension is tracked in CO₂ native preparation #890.

Alternatively, save preparation and inference separately:

rhime prepare --model co2 -c co2.toml --output-dir run/prepare
rhime prior-predictive --model co2 -c co2.toml \
  --preparation-manifest run/prepare/prepare-manifest.json \
  --draws 100 --strict --output-dir run/prior
rhime sample --model co2 -c co2.toml \
  --preparation-manifest run/prepare/prepare-manifest.json \
  --output-dir run/sample
rhime diagnose --posterior run/sample/posterior.nc \
  --sample-manifest run/sample/sample-manifest.json \
  --strict --output-dir run/diagnose
rhime postprocess --model co2 -c co2.toml \
  --sample-manifest run/sample/sample-manifest.json \
  --output-dir run/postprocess

prepare and sample each print one absolute manifest path. Sampling needs only that preparation manifest and current inference choices; postprocessing needs only the sample manifest and current output choices. Separate --prepared-inputs or --posterior arguments are not accepted on these scientific phases. Each phase resolves its own configuration sections; prior readiness requires no posterior sampler or final-product choices. Relative configuration paths resolve from the invocation working directory. Manifest references resolve relative to their declaring manifest; absolute shared-cache references are also supported. Keep manifests and their dependencies.

Compatible BC/offset priors and supported mismatch changes can sample the same preparation into another destination. Per-site model mappings validate every supplied value, including values for dropped sites, require retained-site coverage, then select retained labels. Fixed sigma is nonnegative; OU time scales are positive. Defining native priors, covariance, operators and projections determine coherent preparation and require a coherent new preparation when changed. Full-configuration equality and callable representations do not decide scientific compatibility.

Replay loads saved trace roles, inference provenance and affine associations. It performs no acquisition, preparation, model construction or inference, and returns Co2Output without a live sampler. Missing descriptive facts remain unavailable. Trace and sample records retain the actual algorithm and effective target-accept settings, including whether the matched state step ran. Ordinary sampling without an explicit target_accept delegates to pm.sample and records target_accept_source="pm.sample_default" rather than assuming a numerical default. Replay preserves this marker. Records include package version and Git revision/checkout status when available; unavailable VCS facts are null and do not prevent execution.

prior-predictive --strict exits unsuccessfully for a failed readiness check; unknown checks retain their existing meaning. Invalid returned predictive evidence produces a failed report and retains applicable predictive artifacts. CO₂ execution errors propagate before creating the readiness destination. diagnose assesses the supplied posterior independently of construction; --strict exits unsuccessfully when an available convergence threshold fails. A short smoke test is not evidence of convergence.

Conditional native-flux and country products require prior and posterior flux_scale draws and a companion bound to the preparation used for inference. Enable sampling.sample_prior_predictive to retain prior draws. Missing required draws or incompatible affine inputs fail before product writing. The companion belongs to preparation; country masks are current reporting choices:

[prepared_inputs]
# Alongside the prepared path, requested dates and domain above:
reconstruction_path = "co2-affine.nc"

[outputs]
output_format = "basic"
country_file = "countries.nc"

The affine artifact APIs are described under Summarize conditional CO2 fluxes. Sample replay uses the saved companion; later output choices cannot replace its scientific meaning. Native sources retain their identities; when reporting sectors differ, supply an explicit outputs.source_to_sector mapping. Source sums and sector transforms precede uncertainty statistics. Native-flux and country products carry retained_state_conditional uncertainty scope; they exclude unresolved native-state posterior uncertainty tracked in OPE-68.

Co2Output borrows the preparation and complete annotated trace DataTree, retaining separate prior, posterior, predictive and diagnostic groups with their own coordinates. CO2 retains the original requested window, optional bound affine reconstruction, in-memory products and descriptive provenance. It carries no writing policy or live sampler field. Concentration products deliberately use a derived Dataset with separate prior sample axes; this does not flatten the original trace.

Pass openghg_inversions.rhime.co2.co2_outputs.Co2OutputOptions to calculation and export operations. Its CO₂ fields are output_format (none, basic or paris), output_path, output_name, save_trace, country_file and paris_postprocessing_kwargs. Naming uses the RHIME convention. Reporting source_to_sector mappings are current product choices, separate from saved inference. Standard inversion-output flags and naming options are not accepted. Direct product callers first use validate_co2_product_request(), which checks the selected products and loads compatible reporting masks once; calculation reuses those resolved reporting inputs. Supported products are basic summaries, concentration components and conditional native/country summaries. A later output_format = "paris" request writes supported concentration and flux products from the same samples; it requires the bound companion and an explicit country file. PARIS supports the latest templates, means, native grids and midpoint flux timestamps. inv_out, legacy formats and unsupported PARIS options fail before product writing. See co2_handoffs.py for real coherent preparation, filtering at both edges, full/saved comparison and signed affine products. Co2Output retains the conditional affine meaning; a standard multiplicative InversionOutput cannot represent that reconstruction.

Staged linked CO₂/O₂ commands#

--model co2_o2 selects one joint model with shared GPP/TER/fossil states, separate ocean states and cross-channel aggregation covariance. The CO₂ and O₂ observations can have different lengths, sites and times. Prepare their scientific arrays with openghg_inversions.rhime.co2.prepare_co2_o2_inputs(), then save the Co2O2PreparedInputs artifact to NetCDF or Zarr. Product discovery and campaign policy belong to the caller.

The packaged co2_o2.toml template configures these saved phases. It has no variant selector. A minimal request using the saved independent-error vector is:

format_version = 1
recipe = "co2_o2"

[prepared_inputs]
path = "linked-inputs.nc"
start_date = "2020-01-01"
end_date = "2020-02-01"
domain = "EUROPE"

[channels.co2]
units = "ppm"

[channels.o2]
units = "ppm"

[sampling]
draws = 1000
tune = 1000
chains = 4
nuts_sampler = "pymc"
random_seed = 12345
sample_prior_predictive = 100
sample_posterior_predictive = true

[outputs]
output_format = "basic"
output_name = "linked"
save_concentrations = true

Both configured channel labels and the imported artifact must use the same concentration unit and numerical scale. Heterogeneous CO₂ ppm plus delta(O2/N2) per-meg operation is unsupported until the scientific transform in OPE-86 is defined. The existing numerical codec can retain mixed-unit metadata; that does not establish support for executing such an artifact through these phases.

With the current PyMC 6/Numba backend, native multivariate-normal predictive draws require floatX=float64 in PYTENSOR_FLAGS before starting Python or the CLI. Its float32 random implementation currently fails during compilation; the workflow below is checked with float64. If PYTENSOR_FLAGS is unset:

export PYTENSOR_FLAGS=floatX=float64

If flags are already set, retain the other entries and add or replace the floatX entry with floatX=float64. The application does not override an explicit precision choice.

The default likelihood combines saved independent errors and the complete joint aggregation covariance once. Alternatively configure likelihood.kind = "fixed_ou" with positive tau_hours and nonnegative fixed_site_amplitudes. Linked OU mappings use "co2:MHD" and "o2:MHD" species/site keys. The installed route supports fixed OU amplitudes and requires PyMC for OU sampling. Inferred OU amplitude and cached sampler consolidation remain separate work; existing direct Python runners retain those interfaces.

rhime prepare --model co2_o2 -c co2_o2.toml --output-dir run/prepare
rhime prior-predictive --model co2_o2 -c co2_o2.toml \
  --preparation-manifest run/prepare/prepare-manifest.json \
  --draws 100 --strict --output-dir run/prior
rhime sample --model co2_o2 -c co2_o2.toml \
  --preparation-manifest run/prepare/prepare-manifest.json \
  --output-dir run/sample
rhime diagnose --sample-manifest run/sample/sample-manifest.json \
  --output-dir run/diagnose
rhime postprocess --model co2_o2 -c co2_o2.toml \
  --sample-manifest run/sample/sample-manifest.json \
  --output-dir run/products

Preparation references the imported artifact in place. Retain it with the manifests. Requested dates/domain must be explicit or present in preparation provenance; they are preserved independently of retained observation times. Sampling and prior checks consume current channel/likelihood settings; postprocessing consumes current output settings without loading model or sampler choices. Relative configuration paths use the invocation directory; manifest references use the declaring manifest’s directory. Replacing a preparation invalidates samples associated with its previous generation.

Python callers can use openghg_inversions.rhime.co2.co2_o2_handoffs to save an in-memory preparation, sample from it, and replay products. load_samples and postprocess return a borrowed Co2O2Output retaining the full joint trace, preparation, requested window and recorded inference provenance. Replay constructs no model or sampler. Channel products preserve shared draw labels; keep the joint posterior for cross-channel uncertainty calculations.

basic produces per-channel component summaries and shared retained-state draws; save_concentrations also exports component draws. Contributions retain GPP/TER/fossil, channel ocean, coherent intercept and optional boundary/offset meaning. Mean residuals use observed minus modelled concentrations. Observation predictions are included only when the corresponding predictive draws were saved; replay does not manufacture them.

output_format="none" suppresses derived products while still honoring an explicit save_trace path (or save_trace=true with output_path). Trace destinations must not overlap referenced artifacts or derived product paths, including Zarr directories containing those files.

paris requires prior draws and produces separate CO₂/O₂ concentration products. Optional native_flux_bases and country_file use the existing conditional single-source bucket flux support, with its tracer exclusions; see Save and replay linked prepared inputs and the linked PARIS section in CO₂ model recipes. none suppresses products. Output validation and product calculation precede file writing.

A self-contained synthetic example uses unequal axes and nonzero cross covariance without a private data store:

python -m examples.co2_o2_handoffs /tmp/co2-o2-handoffs

Its short chains exercise persistence, prediction and replay, and do not establish convergence or scientific acceptance.
