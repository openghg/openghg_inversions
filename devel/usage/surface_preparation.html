Surface CO₂/O₂ preparation pilot#

The experimental prepare_surface_site producer calculates continuous-surface CO₂ and O₂ responses without constructing ModelScenario. Existing acquisition defaults remain available. The pilot supports O₂ mole fractions; it does not convert per-meg or APO observations. Column, satellite and flask preparation continue to use their existing owners.

Dependency and precision#

Ordinary boundary sensitivities, observation alignment and flux convolution reuse OpenGHG helpers. Accurate centered boundary normalization and anomaly/mass arithmetic are owned by OGI. The normal installation temporarily pins OpenGHG devel commit b9a9d1f21f22d2f8dcca714283eb936c22338c57. This pilot calls its xarray integrated and time-resolved convolution operations. Both pip and uv installs receive that revision; VG callers need no separate dependency override. Replace this pin with a suitable released minimum before publishing OGI to PyPI. The local curtain kernel does not depend on an unmerged upstream change:

uv sync --locked

The required surface tests exercise the installed provider. Missing required operations fail explicitly. Private provider imports may migrate to public operations later; that transition does not block this workflow.

Centered boundary provenance records boundary_operator_owner="openghg_inversions". The operation uses native boundary/transport inputs, never rounded absolute sensitivities, and records its arithmetic policy revision.

For centered preparation, OGI normalizes all four stable boundary curtains together, using an explicit tolerance for their total raw mass versus unity. Choose that tolerance from the footprint’s justified numerical error. Nonfinite or negative weights, zero mass, and mass outside the tolerance fail validation. Boundary coverage must be declared by time_period interval starts. Concentrations and references are converted to common units before subtraction. Centered preparation arithmetic uses float64; this cannot recover precision already lost in stored input.

Input validation#

Owned views of raw observations, site transport, each source footprint, fluxes and boundary conditions are checked against the corresponding OpenGHG structural schemas at the preparation boundary. Standalone prepare_surface_site checks all raw input roles before provider operations. Fresh acquisition checks raw observations and transport per retained site before resolving observation bins, then checks retrieved fluxes and boundaries once before calculating responses. A shared dataset can serve more than one of these roles. Schema selection follows the integrated, split resolved or legacy resolved fields being consumed. Valid integer spatial labels remain accepted. Validation preserves borrowed payloads, chunks and lazy auxiliary coordinates. Xarray and Pint own alignment and unit conversion; scientific steps own coverage and weight policies.

Explicit source responses#

Observations accept mf or the species name (co2 or o2) as the primary mole fraction. The four ancillary roles use the suffixes _error, _repeatability, _variability and _number_of_observations with either prefix. Each role is resolved independently, so mixed names such as co2 with mf_error are valid. Duplicate aliases for one role fail with the role and variable names. Explicit errors remain available for subsequent preparation.

For supplied observations with another primary name, set observation_variable="measured_concentration". Ancillary aliases keep the same fixed names; a custom primary does not introduce custom error aliases. The selector must identify the only primary candidate. Unrelated extensions, such as co2_quality_flag, keep their names. Only a temporary validation view renames the primary for the provider schema; prepared concentration fields use mf and its documented ancillary names.

With existing OpenGHG data wrappers or xarray datasets:

from openghg_inversions.inversion_data import prepare_surface_site

site = prepare_surface_site(
    observations,
    footprint,
    {"biosphere": biosphere_flux, "fossil": fossil_flux},
    species="co2",
    transport={"biosphere": "time_resolved", "fossil": "integrated"},
    boundary_data=boundary_curtains,
    boundary_representation="centered",
    boundary_reference=400.0,
    boundary_reference_units="ppm",
    boundary_mass_tolerance=justified_mass_tolerance,
    output_units="ppm",
)

Ordinary preparation is the default. Omit boundary_representation and the reference arguments to obtain absolute bc_n/e/s/w contributions. Supply boundary_representation="centered" plus the reference to retain accurate anomaly/mass operands instead. A reference alone never selects centered preparation; Centered preparation requires a justified mass tolerance; ordinary preparation uses OpenGHG’s existing baseline arithmetic without joint mass normalization.

Each source and boundary contribution is calculated at native footprint release times, then averaged to the chosen observation cadence. Each source is convolved independently. time_resolved includes both its resolved history and its monthly residual; adding an integrated response for that same physical contribution would double count it. Modes describe distinct physical contributions, not inference state groups. fp_x_flux_sectoral retains source and grid labels; fp_x_flux is its explicit source sum. Explicit surface source labels are sorted. Response concentrations use observation units or the explicit output_units. Spatial axis order follows labelled inputs, with time placed last. Signed fluxes are retained. Fluxes need regular declared validity, complete backward history and complete calendar months containing the releases used by the resolved residual. Resolved lag coordinates must be regular, nonnegative whole hours, with spacing that divides 24 hours. Release and flux intervals remain whole hours; their absolute timestamp phases may differ. The release/lag transport grid must fit the provider rolling window and selected lag labels. Coarser flux intervals, including two-hour flux on an hourly transport grid, are supported when their cadence fits the resolved history window. A cadence longer than that window is rejected because the provider would otherwise substitute monthly flux for the resolved calculation. Gaps and inadequate coverage fail explicitly.

For distinct source footprints, pass a source-to-footprint mapping as the second argument and supply site_footprint_data=... explicitly. That separate footprint owns observation alignment, shared filter fields and boundary transport. Each source response must match the resulting observations and spatial grid. A source label or mapping order never chooses the site’s boundary transport.

Inputs are borrowed. The producer owns shallow metadata containers around provider calls; payload calculations remain lazy where supported. Provider observation alignment can evaluate observation-validity masks to select rows. Preparation and model materialization remain explicit execution boundaries.

Retrieval and retained native flux#

MergedData.from_options adds an opt-in beside the existing scenario route:

from openghg_inversions.inversion_data import MergedData, SiteOptions

selectors = SiteOptions.from_inputs(
    sites=["MHD"], averaging_period="1h", inlet="10m", fp_height="10m",
    time_resolved=True,
)
merged = MergedData.from_options(
    species="co2", domain="EUROPE",
    start_date="2020-01-01", end_date="2020-02-01",
    site_options=selectors, flux_sources=["biosphere", "fossil"],
    surface_transport={"biosphere": "time_resolved", "fossil": "integrated"},
    use_bc=True, boundary_representation="centered",
    reference=400.0, reference_units="ppm",
    mass_tolerance=justified_mass_tolerance,
)

Pass the appropriate store and dataset selectors for your installation. This route delegates to acquire_surface_data and shares concrete observation and footprint retrieval with the existing scenario route. It retains observation averaging, calibration, inlet/height selection, missing-site handling, explicit total observation errors and flux sanitation.

Acquisition retrieves retained observations and footprints before flux. It uses one observation-role resolution, unit conversion and coarsest alignment per retained site, reusing those arrays and native release bins for preparation. It then combines the actual backward history and complete release-month residual support across retained sites and sources. A 24-hour history is the usual case; 120-hour histories also use their actual lag coordinates. No fixed history cap or preceding-month assumption is imposed. Legacy fp_HiTRes excludes its final residual entry when deriving resolved history. Unused releases and dropped sites do not enlarge the request. A history that crosses a month boundary requires its actual preceding hours, rather than the full preceding month.

All sources are queried over the common required span so mixed integrated and resolved modes can retain compatible native axes. Retrieval includes the preceding declared intervals, including calendar labels offset from month or year starts. The getter resolves one common effective span for all sources; when period metadata are absent, a returned cadence can trigger one bounded common earlier request without applying source padding again. The full retrieved native flux support is retained. Explicit surface native prior-flux reporting sorts source labels and converts to the first sorted source’s flux units. Default acquisition retains source insertion order. Older-inventory relabelling and climatological year reuse are disabled.

When a boundary period is declared, both acquisition routes include the interval governing a mid-period start and preserve its native timestamp.

Selected identities are captured at retrieval in owned wrapper metadata while borrowing the datasets. Preparation combines those facts with transport metadata and serializes provenance once. Combined observation versions remain unknown when retrieval did not preserve them; combined footprint identifiers retain their order.

The surface preparation policy revision records the scientific ordering: form native source products before averaging onto observation bins. It is independent of prepared-input schema versions and manifest format versions, which describe serialized artifacts.

Fresh acquisition requires compatible native source axes for retained-flux reporting. Standard/multisector scientific preparation of a supplied surface MergedData applies the same exact-axis policy, converting units before stacking or summing. Mixed-cadence observation-space responses can be calculated with prepare_surface_site; they do not yet define a common native reporting axis or an affine flux companion. Supply an independently justified native representation before using such products. This pilot does not construct the ordinary CO₂ coherent reduction automatically; see Coherent Gaussian Reduction and CO₂ model family.

Centered preparation handoff#

Apply supported observation selection first, then derive missing observation errors with prepare_observation_errors on the retained population. Explicit existing errors remain unchanged. Project the native bc_anomaly_* and bc_mass_* arrays through the same chosen BC basis using bc_sensitivity or build_sensitivities. Their outputs are H_bc_anomaly (A), H_bc_mass (M) and scalar bc_reference (c). They retain spatial BC labels through gathering. The reference must agree across sites within a tracer.

The source-neutral adapter accepts these projected operands (choose the summed response for a shared source-scaling field, or a compatible source-resolved flux basis for separate fields):

from openghg_inversions.basis._helpers import bc_sensitivity
from openghg_inversions.inversion_data import prepare_rhime_inputs_from_xarray
from openghg_inversions.rhime.preparation import filter_observations, prepare_observation_errors

selected, retained_selectors = filter_observations(
    {"MHD": site}, selectors, filters=["daytime9to5"],
)
with_errors = prepare_observation_errors(selected, averaging_error=True)
projected = bc_sensitivity(with_errors, chosen_boundary_basis)
canonical = prepare_rhime_inputs_from_xarray(
    {name: data.drop_vars("fp_x_flux_sectoral") for name, data in projected.items()},
    basis_functions=chosen_flux_basis, averaging_period="1h",
)

Selection filters preserve aligned operands and scalar references. Preparation owns spatial bc_basis_algorithm="NESW" or explicit bc_basis_paths; frequency and anchor belong to the model. Old rounded H_bc alone cannot recover accurate centered operands.

These preparation operands are the handoff for centered CO₂ model integration. Centered likelihood binding and absolute prediction replay are delivered in the following inference change.

Linked CO₂/O₂ preparation can retain centered operands in memory. Its dedicated prepared-input serialization does not yet support those operands; to_datatree and save reject them explicitly. Persistence belongs to the later centered output integration. Standalone CO₂ prepared inputs retain the raw operands through their existing input-dataset serialization.
