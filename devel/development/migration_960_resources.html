Migration resource evidence for issue 960#

This is the resource-selection part of the M1 migration evidence. It records observed compatibility behavior and candidate replacements for reviewers of issue 960. Candidates below are not decisions about the future converter.

Revisions and evidence classes#

Executed current evidence (C): compatibility-bearing devel commit 0a32d73a5c4a72be0505a4ed682472e1613e49e9. The 14 checks in tests/test_migration_960_resources.py execute resource selection and request decoding only. They use temporary synthetic NetCDF files and no acquired data, model construction or inference. The files carry a partition variable or the retained-artifact schema marker; a schema marker alone is not a valid complete retained scientific artifact.

Historical source inspection (H): published v0.7.4 commit 0e5d6ef76eb724da8cee1b780633578bdc05f2b4. Resource findings were checked directly against basis/_functions.py, basis/_wrapper.py, basis/_helpers.py and utils.py at that revision. Those sources were also compared with published v0.7.3 (9c0d23c15000dc7a7e4c3306d3f1bfd4816bdb4f); the relevant source files are unchanged. H does not mean the historical resource workflow was executed.

The true historical route was traced explicitly: run_hbmcmc.py dispatches --legacy-fixedbasis to fixedbasisMCMC; that calls hbmcmc/preparation.py:prepare_fixedbasis_inversion_data, which imports basis_functions_wrapper from basis/__init__.py. That public export selects basis/_wrapper.py; its saved-basis branch calls load_basis_functions and its BC branch calls basis/_helpers.py’s bc_sensitivity. Thus H in the ledger applies to the true legacy route, even though those basis helpers were also shared with historical RHIME. At the pinned current revision the true executor is already absent; C here tests the resource adapter used by the ordinary wrapper and does not imply a current --legacy-fixedbasis execution.

Target decision (T): an unresolved converter policy or scientific review. Follow-up owners are the issue workstreams identified below, not an assertion that a person has accepted an assignment.

Fixture format and rerun#

tests/fixtures/migration_960/resources/cases.json contains original inputs, small synthetic directory layouts, plain expected settings or exact current errors, and a justification for each expectation. Expected path strings are relative to the test invocation directory. files declares each synthetic file as a partition or retained schema marker; the test driver writes those files without deriving any expected result from the adapter. The expectations were transcribed from source branches and checked against historical implementations and existing resource-boundary tests where applicable; they were not generated by serializing adapter output. The fixture data has no Python/HBMCMC imports and can survive deletion of the current execution driver.

In the lean environment for the pinned current revision, first apply the cache and thread environment setup in Migration evidence before compatibility removal, preserving any existing PyTensor flags, then run:

.venv/bin/pytest -q tests/test_migration_960_resources.py

Observed result: 14 passed on CPython 3.13.7. Ruff passed for this test module. Interpreter/dependency and released-baseline provenance belong to the parent migration evidence note. Historical directory defaults, read-permission filtering, support-map content, relative packaged outer-map fallback, and complete retained artifact loading remain inspection-only in this bounded resource characterization. No inference equivalence is claimed.
