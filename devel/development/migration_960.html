Migration evidence before compatibility removal#

This is the bounded M1 evidence archive for issue #960, part of #944 / #948. It serves maintainers removing compatibility and authors of the later explicit converter. It records source behavior, not a new configuration contract or a promise of numerical reproduction. Production code and behavioral specifications are unchanged by this evidence PR.

Read the ledger together with the plain inputs and expected observations in tests/fixtures/migration_960/. Those files do not import HBMCMC and remain available after its deletion. Runtime characterization tests deliberately call the existing boundary: deletion PRs must account for their affected cases and retain the plain expectations for later converter checks. Runtime-only drivers may retire with their adapters before the converter exists; scientific regressions must be ported in the removal PR. Do not regenerate expected values from the replacement translator.

  • Migration resource evidence for issue 960

Evidence vocabulary and pinned comparison#

  • Observed means a bounded check was executed with acquisition and sampling absent or replaced by a capture stub. It establishes settings or errors, not a successful scientific inversion.

  • Inspected means the pinned source body/signature establishes the statement; no execution of that scientific case is claimed.

  • Candidate identifies a possible modern spelling or policy. It does not resolve the release’s API, support window, or scientific choices.

  • Mechanical preserves the represented setting; scientific change needs an explicit choice or acknowledgement; unsupported stays in its source environment; unresolved has an identified follow-up owner.

The verified compatibility-bearing development and comparison revision is 0a32d73a5c4a72be0505a4ed682472e1613e49e9 (devel fetched on 22 October 2026). It still contains hbmcmc/compatibility.py and hbmcmc/run_hbmcmc.py. This is also the production revision exercised by this PR; the evidence-only commits change no production modules. The earlier 6a0d6acf audit is not the baseline. A fresh diff from that commit found no changes in the HBMCMC package, rhime/_runner_compat.py, requests.py, ini.py or config/config.py; current cli.py and model code were also read. See the historical page for exact released tag commits, publication status and the separately prepared main version.

Future removal PRs must compare their base to this exact revision and refresh any affected ledger entries, inputs, expected observations and tests. For example:

git diff 0a32d73a5c4a72be0505a4ed682472e1613e49e9..HEAD -- \
  openghg_inversions/hbmcmc openghg_inversions/rhime \
  openghg_inversions/config openghg_inversions/_flux_options.py \
  openghg_inversions/cli.py openghg_inversions/inference \
  openghg_inversions/models openghg_inversions/postprocessing

Current development environment#

The focused checks use a new worktree-local lean environment made with uv sync --locked; no historical dependency was installed into it. Interpreter: CPython 3.13.7, Clang 20.1.4, Linux. uv.lock at the pinned development ref has SHA256 a60675ff1116d759773ad94a3f71d265c4ac330a232dc4f021891d12031acf3c. The installed project reports version 0.7.4 from development metadata; that string does not identify the released v0.7.4 code.

Resolved versions used here: PyMC 6.3.2, PyTensor 3.3.2, ArviZ 1.3.0, NumPy 2.2.6, SciPy 1.15.3, xarray 2025.9.1, OpenGHG 0.19.0, Dask 2026.1.1, sparse 0.17.0, pytest 9.0.2 and Ruff 0.16.0. The pinned lockfile provides the remaining dependency provenance. Historical provenance and limitations are recorded separately; do not loosen modern requirements to run old source.

Rerun the bounded checks#

Check out this evidence PR to obtain the fixtures/tests, keeping its pinned production source, then create its lean environment:

uv sync --locked
export DASK_NUM_WORKERS=2 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
export MPLCONFIGDIR=/tmp/mpl-960
IFS=',' read -r -a inherited_flags <<< "${PYTENSOR_FLAGS:-}"
export PYTENSOR_FLAGS=base_compiledir=/tmp/pytensor-960
for flag in "${inherited_flags[@]}"; do
    case "${flag//[[:space:]]/}" in base_compiledir=*|'') continue ;; esac
    PYTENSOR_FLAGS+=",$flag"
done
.venv/bin/pytest tests/test_migration_960_requests.py tests/test_migration_960_resources.py
.venv/bin/ruff check tests/test_migration_960_requests.py tests/test_migration_960_resources.py
git diff --check

The tests use only small local files and synthetic arrays. They do not acquire real data, sample a posterior, submit an inversion or validate arbitrary user scripts. Use the historical page’s isolated environment instructions for released-source observations. Environment-creating tox runs on this cluster must use sbatch scripts/slurm_tox.sh; no such environment is needed for these bounded direct checks.

Removal and validation handoff#

Under the #961 development boundary, the retirement delivery checklist records concrete owners, order and baseline checks. Each PR removing or deliberately changing migration-relevant behavior must:

  • Identify affected ledger entries and plain cases. Add bounded evidence for newly discovered behavior before removal, keeping source version and route explicit.

  • Compare its base and affected source with pinned revision 0a32d73a5c4a72be0505a4ed682472e1613e49e9, accounting for intervening changes and relevant merged PRs.

  • Record disposition and follow-up owner: retained, mechanically migrated, deliberate scientific change, unsupported or unresolved. Preserve historical inputs and expectations; add dated comparisons rather than replacing them with modern output.

  • Preserve or port relevant scientific expectations before retiring adapter/test plumbing. Test unchanged behavior on canonical inputs and agreed scientific changes against their new semantics. Distinguish inspected evidence from executed checks and link validation to the implementation revision.

This remains a pinned source archive. Only affected evidence and live checks need refreshing; neither a whole-audit rerun nor finished converter/launcher tooling is required for every removal. Passing translation tests alone does not establish scientific parity. The gate does not resolve pending interface or scientific choices. #719 owns runtime removal and relevant regression migration; #961 amends the compatibility promises without itself implementing removal. See Migrate from HBMCMC to RHIME for the amended requirements and retained capabilities. #948 owns the final supported source versions and target choices; #949/#950 own conversion and launch tooling; #952 owns integrated scientific and packaging acceptance. Independent basis readers/writers remain with #951.

The existing regression inventory includes tests/test_rhime_compatibility.py, test_run_hbmcmc_shim.py, test_rhime_configuration.py, test_acquisition.py, test_filters.py, test_basis_paths.py and test_unsupported_tracer.py. Shared ground/satellite request fixtures in tests/conftest.py still contain emissions_store and emissions_name. This is an inspection inventory, not a claim that all those scientific tests were executed here or an authorization to delete them. Preserve scientific expectations on canonical inputs in the affected removal PRs.

Observed validation on 22 October 2026#

The new request/resource checks and the existing unsupported-tracer checks passed: 56 tests. The related compatibility, wrapper, configuration, output-resource, BC-resource and resource-boundary modules passed: 295 tests. The broader invocation was:

.venv/bin/pytest tests/test_rhime_compatibility.py \
  tests/test_run_hbmcmc_shim.py tests/test_rhime_configuration.py \
  tests/test_rhime_output_resources.py tests/test_bc_basis_resources.py \
  tests/test_rhime_resource_boundaries.py

Use the environment setup above for both commands. The new tests comprise 26 request checks and 14 resource checks; the modern chain-summary witness uses only modern postprocessing and the archived plain values. Changed-path Ruff and git diff --check passed. The historical page records its separate successful harness and installed-command observations.

The three new pages were rendered with Sphinx 9.1.0, Docutils 0.22.4 and the repository’s PyData theme 0.21.0 in an existing documentation environment. This bounded build copied only these pages, used migration_960 as its root, and treated warnings as errors; outgoing :doc: references to omitted pages were checked against the full source tree separately. The generated headings, ledger tables, navigation and code blocks were checked in the built HTML. This does not claim a full API/tutorial documentation build.

No full scientific test suite, Python 3.12 modern matrix or CI-equivalent tox run is claimed. Final cross-version, packaging and scientific acceptance remains with #952. Source-inspected equations, historical resources, arbitrary external scripts and the final supported patch-version subset retain their stated limits.
