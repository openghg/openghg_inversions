Merged-input schemas#

These references are generated from the live xarray-validate schema factories used by MergedData.validate_scientific_inputs. They describe selected preparation variants, rather than prescribing a single layout for every recipe. Other combinations use the same factories with different keyword arguments. See Customising RHIME for the preparation workflow and unit policy.

Data types describe decoded, in-memory xarray data, not the on-disk representation. For example, a file may store numeric time offsets with CF units and calendar attributes; xarray decodes these before validation. The time coordinates in these schemas must be datetime64 after decoding. Dates decoded to cftime objects do not satisfy that dtype requirement.

Each table distinguishes required fields, optional pattern matches, and allowed extras. Dimensions are ordered unless the table says otherwise; an empty dimension list means a scalar. Dtypes such as integer and floating denote whole NumPy dtype families. Relationship descriptions come from the validation callbacks’ docstrings; those callbacks are not executed to build this page.

This reference describes metadata validation. It does not establish finite numerical values or replace the checks owned by projection and graph construction. The generated description is for documentation, not executable schema restoration.
