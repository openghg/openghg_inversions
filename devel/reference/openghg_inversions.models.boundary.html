openghg_inversions.models.boundary#

Boundary-condition components for RHIME recipes.

Names here are short because the package supplies the context: a Choice is a boundary choice and Outputs are boundary outputs. Runners and builders conventionally name their parameter boundary, which shadows the package, so they import Choice and Bound directly (boundary: Bound | None).

The package has four layers, followed in this order by one boundary from configuration to a saved trace:

Layer

Records

Modules

Sensitivity contracts: what the arrays guarantee

RawCenteredSensitivity, BoundCenteredSensitivity, BoundAdditiveSensitivity (static types on xr.Dataset)

contracts; binding uses bind_period_states()

Families: the scientific prior

a choice and a bound record per family, typed by the Choice and Bound protocols

multiplicative, additive, anomaly_scaling

Shared centered pieces: the term inside the model

CenteredBoundary, its RegisteredSensitivity, MeanShift, Correction, and the additive Anomalies

centered, additive_anomalies

Handoffs: what recipes and outputs receive

AffineConcentrationTerm from add, Outputs from outputs

openghg_inversions.models.components, outputs

A choice (MultiplicativeChoice, AdditiveChoice, AnomalyScalingChoice) is one resolved selection of the user’s boundary options (priors, activity, anomaly structure and scale, reference and the boundary period calendar) before any arrays are attached. Each choice class names its family in kind, which configuration selects explicitly with type and outputs record as boundary_formulation. Configuration adapters produce choices; bind_prepared() binds one to the sensitivity representation that preparation produced. choice.bind(observations, sensitivity) binds centered sensitivity, and an AbsoluteChoice’s bind_absolute binds absolute H_bc. Either returns the bound record (CenteredMultiplicativeBoundary or, from bind_absolute, MultiplicativeBoundary; AdditiveBoundary; AnomalyScalingBoundary), which pairs the choice with borrowed labelled sensitivity aligned to one fit’s observation rows and expanded to its boundary periods.

A recipe binds each boundary once, materializes the bound record together with its other inputs (dask.compute traverses these dataclasses, including choice priors; see to_dense_tree()), then calls boundary.add(...) inside its registered model. add is the affine counterpart of add_linear_component(): it registers the sensitivity, adds the sampled corrections and returns an AffineConcentrationTerm, which ordinary and cached likelihoods consume without knowing the family, and boundary.outputs() declares the roles, units and metadata recorded with the trace. Choice and Bound are structural protocols, so adding a centered boundary family means adding one module with a choice and a bound record inheriting CenteredBoundary, plus its configuration adapter and tests; nothing here enumerates the families.

Sensitivity is either absolute H_bc or centered A, M and c with H = A + c M. Preparation and loading establish RawCenteredSensitivity; BoundCenteredSensitivity.bind() produces BoundCenteredSensitivity, which every centered family consumes; and weighted additive anomalies extend it to BoundAdditiveSensitivity. Every Choice binds raw centered sensitivity; only MultiplicativeChoice is also an AbsoluteChoice, whose bind_absolute binds absolute H_bc to MultiplicativeBoundary, the one bound record that does not inherit CenteredBoundary. bind_prepared() is the one place that checks a choice against the representation preparation produced. Centered sensitivity keeps small anomalies after cancellation: likelihoods use observations shifted by the fixed c M 1, while absolute outputs add it back. Centered graphs need a float64 PyTensor process (require_centered_precision()), checked once when centered sensitivity is bound.

Validation happens where data enters: preparation and artifact loading establish the raw contract’s units, labels and layout; binding owns calendar and row alignment and establishes the bound contract by construction; add checks values that only become available once lazy payloads are materialized.

add(*, output_dim='nmeasure', prefix='', owner='bc')#

Add the mean shift, anomalies and boundary concentration to the current model.

Must be called inside an active PyMC model that has the coordinate registry, after data has been materialized jointly with the other model inputs. It registers the sensitivity, reference, scale and any weights, basis or indicators as model data, plus the sampled variables and their deterministic responses.

Parameters:

  • output_dim (str) – Observation dimension registered by the model.

  • prefix (str) – Prefix for graph variable names.

  • owner (str | None) – Namespace for component-owned boundary-state coordinates; None keeps the local names such as bc_region. Graph names are controlled separately by prefix.

Returns:

output is the absolute boundary concentration mu_bc; the likelihood contribution omits the fixed c M 1, which is the reference shift; the fixed contribution is A 1; the affine blocks are the mean response (M 1, or M summed over each period’s states) followed, with anomalies, by M B (M itself for independent anomalies) with their physical coefficients; and the sampled variables are the mean latent and anomaly coordinates.

Return type:

The boundary term

Raises:

  • ValueError – If output_dim is not the bound observation dimension, data is still lazy, materialized operands or weights are invalid, or a whole-window mean prior is not scalar.

  • RuntimeError – If the model lacks the coordinate registry.

class AdditiveChoice(
mean_prior,
anomaly_scale,
anomalies='weighted',
mean_by_period=False,
frequency=None,
anchor_time=None,
)#

Bases: object

Prior specification for additive boundary corrections, before binding.

A choice holds the scientific options (mean shift prior, anomaly structure and width, and boundary period calendar) without bound observations or sensitivity arrays. bind() pairs it with one fit’s observations and centered sensitivity.

Variables:

  • mean_prior (collections.abc.Mapping[str, Any] | None) – Prior for the mean shift in observation concentration units, scalar or one shift per period with mean_by_period; or None for no mean shift. None is allowed only for sampled period contrasts or independent anomalies.

  • anomaly_scale (float) – Finite non-negative Gaussian standard deviation of the anomaly coordinates, in concentration units. Zero keeps only the mean shift.

  • anomalies (Literal['weighted', 'period_contrasts', 'independent']) – Anomaly structure: "weighted" (requires prepared centering weights), "period_contrasts" or "independent".

  • mean_by_period (bool) – Fit one independent mean shift per boundary period; requires a mean prior and a frequency.

  • frequency (str | None) – Boundary period frequency, with the syntax and calendar of bc_freq: None for one period over the window, "monthly" for calendar months, or a positive fixed-duration string such as "7D".

  • anchor_time (str | datetime.datetime | numpy.datetime64 | pandas._libs.tslibs.timestamps.Timestamp | None) – Origin of fixed-duration periods; only valid with a fixed-duration frequency. None uses the earliest selected observation of the fit. The RHIME parameter adapter instead defaults bc_freq_anchor to the configured start date.

Raises:

ValueError – On construction, for an unknown anomaly structure, a negative or non-finite scale, a missing mean prior where one is required, mean_by_period without a mean prior or frequency, or an invalid frequency or anchor.

property mean_shift: MeanShift#

The mean shift these options define; without a prior it adds nothing.

class BoundCenteredSensitivity(data_vars=None, coords=None, attrs=None)#

Bases: Dataset

Centered boundary sensitivity bound to one fit’s rows and periods.

Structural guarantees, checked by validate():

  • H_bc_anomaly and H_bc_mass share dimensions (observation, "bc_region") in that order. The observation dimension is, by convention, H_bc_anomaly.dims[0] (observation_dim()); it has a unique eager index whose labels order the fit’s rows.

  • bc_region is a unique MultiIndex with levels ("bc_curtain", "bc_period"): every bound state is one curtain in one boundary period, including curtains unobserved in that period.

  • The operands have real integer or floating dtypes; bc_reference is scalar.

  • H_bc_anomaly and bc_reference carry the same nonempty concentration unit string; H_bc_mass has units '1'.

  • Other variables are permitted, including the additive extension’s bc_centering_weights.

This contract establishes structure only. Numerical requirements remain with the explicit later numerical operation, as for raw sensitivity. Binding selects and masks rows, so even nonzero raw mass may become all zero.

class RawCenteredSensitivity(data_vars=None, coords=None, attrs=None)#

Bases: Dataset

Prepared centered boundary sensitivity on raw spatial boundary states.

Structural guarantees, checked by validate():

  • attrs["boundary_representation"] == "centered-v1".

  • H_bc_anomaly and H_bc_mass share the dimensions bc_region and one raw observation dimension, time when the anomaly has it and otherwise nmeasure, in either order. Both dimensions have unique eager indexes, and bc_region is a plain spatial index, not the bound (bc_curtain, bc_period) MultiIndex. Neither operand is marked as expanded by boundary_sensitivity_preparation.

  • The operands have real integer or floating dtypes; bc_reference is scalar.

  • H_bc_anomaly and bc_reference carry the same nonempty concentration unit string; H_bc_mass has units '1'. An mf variable, when present, has the same concentration units.

  • Optional bc_centering_weights lie on (bc_curtain, bc_period) with unique curtain labels, interval-start DatetimeIndex periods and units equivalent to '1'. Only weighted additive anomalies consume them.

  • Other variables are permitted. An absolute H_bc diagnostic must be marked boundary_sensitivity_preparation='unexpanded'.

Numerical requirements are not established by this lazy-stage contract. After the recipe jointly materializes the operands, the explicit numerical operation checks finite A and c and finite, non-negative, nonzero M; weighted additive operations also check finite, strictly positive weights.
