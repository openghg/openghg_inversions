Customising RHIME#

RHIME is built from reusable functions for data preparation, basis construction, model construction, sampling, and output. This is a deliberate design choice: when the standard workflow does not express the science you need, you should be able to start from a working example and replace the smallest relevant part.

The examples on this page use a procedural style. Data is passed from one function to the next in the order that the inversion runs, so readers do not need to design a new class hierarchy or framework before changing a model. Some library functions return structured objects that group related values, but the examples show how to use those objects directly.

Reusing the components does not make every custom workflow automatic. A replacement function is responsible for the scientific choices it introduces, and a deeper change may also need different data preparation. The remaining RHIME stages can only validate the inputs and assumptions covered by their documented interfaces.

Choose the smallest starting point that fits the change:

  • To change only the likelihood, pass a Python function to run_rhime.

  • To change a preparation stage such as basis construction, copy the visible runner and replace that stage.

  • To start from prepared data or replace the complete model, use run_rhime_from_prepared_inputs.

Change the likelihood with a Python function#

For an ordinary likelihood variation, keep RHIME’s complete acquisition-to-output workflow and pass one Python function to run_rhime. The function is deliberately unavailable to INI files: it is not imported from configuration or stored in a run or model specification.

The complete integration is one named argument:

from my_project.likelihoods import likelihood_builder
from openghg_inversions.rhime import run_rhime

result = run_rhime(
    config_file="config.ini",
    likelihood_builder=likelihood_builder,
)

RHIME calls the function as likelihood_builder(context) while constructing the PyMC model. It returns a RhimeLikelihoodResult, which contains the new observed variable and the small amount of information RHIME needs for sampling and output. An ordinary caller does not construct the context or these supporting records.

Editable likelihood#

The following example replaces RHIME’s Gaussian observation distribution with a Student-t distribution while reusing RHIME’s current mean and error construction:

 1"""Editable Student-t likelihood shared by both RHIME examples.
 2
 3This project-owned function changes RHIME's observation distribution while
 4reusing its current mean and error construction. It demonstrates the result
 5roles, compatible outputs, and JSON-compatible metadata that a likelihood
 6builder owns.
 7
 8``likelihood_builder`` is the exported runner seam. Importing this module does
 9not build a model, retrieve data, sample, or write outputs.
10"""
11
12import pymc as pm
13
14from openghg_inversions.rhime import (
15    RhimeLikelihoodContext,
16    RhimeLikelihoodResult,
17    build_rhime_observation_state,
18    select_aggregation_error_mode,
19)
20
21
22def likelihood_builder(context: RhimeLikelihoodContext) -> RhimeLikelihoodResult:
23    """Build a Student-t observation model with RHIME's current error scale.
24
25    Degrees of freedom are fixed at 4.0. RHIME's ``epsilon`` is passed as the
26    Student-t scale, not its marginal standard deviation; for four degrees of
27    freedom the marginal standard deviation is ``epsilon * sqrt(2)``.
28
29    Args:
30        context: Labelled RHIME means, observations, and error settings for
31            the active PyMC model.
32
33    Returns:
34        Observed Student-t variable with semantic roles, conservative output
35        support, and serializable provenance metadata.
36
37    Raises:
38        ValueError: If dense or low-rank aggregation error would require a
39            multivariate Student-t likelihood.
40
41    Notes:
42        On success, this adds RHIME's named observation-state nodes (``Y``,
43        ``error``, ``min_error``, and ``sigma`` or ``epsilon`` as applicable)
44        plus ``student_y`` to the active PyMC model. It performs no sampling or
45        output writes. Unsupported aggregation modes are rejected before any
46        nodes are added.
47    """
48    aggregation_error_mode = select_aggregation_error_mode(
49        context.data,
50        context.aggregation_error_mode,
51    )
52    if aggregation_error_mode not in {"none", "diagonal"}:
53        raise ValueError("This Student-t model assumes independent observations.")
54    state = build_rhime_observation_state(context)
55    observed = pm.StudentT(
56        "student_y",
57        nu=4.0,
58        mu=state.mean,
59        sigma=state.error_scale,
60        observed=state.observed,
61        dims=context.output_dim,
62    )
63    return RhimeLikelihoodResult(
64        likelihood=observed,
65        error_scale=state.error_scale,
66        variable_roles={
67            "concentration": "student_y",
68            "model_error": "epsilon",
69        },
70        supported_output_formats=("none", "inv_out"),
71        metadata={"family": "student_t", "degrees_of_freedom": 4.0},
72    )
73
74
75__all__ = ["likelihood_builder"]

RHIME records the function’s module and name, together with its likelihood metadata, in the result and in saved output. It does not copy the Python source code into the output, so a project should keep the source and environment used for an inversion.

The returned RhimeLikelihoodResult maps standard meanings to the PyMC variable names used by this model. For example, it tells RHIME that student_y is the modelled concentration and epsilon is the model-error scale. Sampling and output code can then find these quantities even though the custom model uses different names. It also lists the output formats that have been checked with this likelihood; this example supports no file output (none) and the inv_out format. The Student-t family and degrees of freedom are stored as simple metadata.

The example rejects dense and low-rank aggregation covariance because it uses an independent Student-t distribution. Supporting those aggregation-error modes would require a multivariate likelihood.

Optional project CLI#

The short wrapper below packages the same one-call integration as a reusable Python function and command-line entry point:

  1"""Run ordinary RHIME with a project-owned Student-t likelihood.
  2
  3This is the preferred low-ceremony customization route. It keeps RHIME's
  4complete acquisition-to-output pipeline and changes only the direct-Python
  5likelihood callable passed to :func:`openghg_inversions.rhime.run_rhime`.
  6Use :func:`run_with_likelihood` from Python or :func:`main` from the command
  7line with a normal RHIME configuration. The workflow may retrieve or reload
  8data, materializes related model arrays together at the named PyMC boundary,
  9samples, and writes requested outputs while canonical xarray/Dask inputs remain
 10borrowed.
 11"""
 12
 13from __future__ import annotations
 14
 15import argparse
 16from collections.abc import Sequence
 17import json
 18from pathlib import Path
 19from typing import Any
 20
 21from openghg_inversions.rhime import RhimeResult, run_rhime
 22
 23from .likelihoods import likelihood_builder

 26def run_with_likelihood(
 27    *,
 28    config_file: str | Path | None = None,
 29    **kwargs: Any,
 30) -> RhimeResult:
 31    """Run standard RHIME with a project-owned Student-t likelihood.
 32
 33    Args:
 34        config_file: Optional RHIME INI configuration file.
 35        **kwargs: Standard RHIME option names that override values from
 36            ``config_file``.
 37
 38    Returns:
 39        The sampled result and any outputs requested by the RHIME options.
 40
 41    Raises:
 42        TypeError: If the likelihood builder returns an invalid result type.
 43        ValueError: If required options are missing, aggregation or output is
 44            unsupported, or likelihood roles or metadata are invalid.
 45
 46    Notes:
 47        This workflow may retrieve or reload data, materializes related model
 48        arrays together at the named PyMC boundary without mutating canonical
 49        prepared inputs, runs sampling, and writes configured outputs.
 50    """
 51    return run_rhime(
 52        config_file=config_file,
 53        likelihood_builder=likelihood_builder,
 54        **kwargs,
 55    )
 56
 57
 58def _json_object(value: str) -> dict[str, Any]:
 59    """Parse one command-line JSON object containing RHIME option overrides.
 60
 61    Args:
 62        value: JSON text to parse.
 63
 64    Returns:
 65        The decoded JSON object.
 66
 67    Raises:
 68        argparse.ArgumentTypeError: If the text is invalid JSON or decodes to
 69            a non-object value.
 70    """
 71    try:
 72        parsed = json.loads(value)
 73    except json.JSONDecodeError as exc:
 74        raise argparse.ArgumentTypeError(f"invalid JSON: {exc.msg}") from exc
 75    if not isinstance(parsed, dict):
 76        raise argparse.ArgumentTypeError("--kwargs must decode to a JSON object")
 77    return parsed
 78
 79
 80def main(argv: Sequence[str] | None = None) -> RhimeResult:
 81    """Parse command-line options and run the customized RHIME workflow.
 82
 83    Args:
 84        argv: Command-line tokens excluding the program name. ``None`` reads
 85            tokens from :data:`sys.argv`.
 86
 87    Returns:
 88        The RHIME result returned by :func:`run_with_likelihood`.
 89
 90    Raises:
 91        SystemExit: If argument parsing fails or help is requested.
 92    """
 93    parser = argparse.ArgumentParser(description=__doc__)
 94    parser.add_argument("config_file", nargs="?", type=Path, help="RHIME INI configuration file")
 95    parser.add_argument(
 96        "--kwargs",
 97        type=_json_object,
 98        default={},
 99        metavar="JSON",
100        help="additional RHIME options as a JSON object",
101    )
102    args = parser.parse_args(argv)
103    return run_with_likelihood(config_file=args.config_file, **args.kwargs)
104
105
106if __name__ == "__main__":
107    main()

Run it with a normal RHIME configuration and optional JSON overrides:

python -m package_name.run_with_likelihood config.ini \
    --kwargs '{"output_path": "outputs", "output_format": "inv_out"}'

run_rhime_multisector accepts the same Python-only builder contract. The standard multi-sector model retains sector flux components and roles, then passes their combined observation mean to the likelihood, so no special case or semantic compromise is required.

Use the seam from a generated project#

Create a normal downstream package with the current OpenGHG project cookiecutter:

uvx cookiecutter gh:openghg/openghg-project-cookiecutter

The template already declares openghg and openghg_inversions as dependencies and creates a src layout. Add the project-owned files beside the generated package’s existing modules, without copying any OpenGHG Inversions implementation:

src/my_inversion/
  __init__.py
  likelihoods.py
  runner.py
tests/
  test_runner.py

The example and its package-shaped test use only documented names from openghg_inversions.rhime. Pin the release or commit used for a scientific run in the downstream project’s lockfile. An optional RHIME recipe or generated-project CI in the generic cookiecutter would be a separate cross-repository change and is not required for this workflow.

Copy the complete runner#

The copied runner below is an advanced, version-coupled escape hatch for scientific changes beyond the likelihood seam. It makes the major stages visible while importing their implementations from the supported public RHIME API. Prefer run_rhime_from_prepared_inputs when replaying prepared inputs, replacing the complete model, or deliberately starting from a different preparation graph.

The deliberate change is the likelihood passed to build_standard_rhime_model: the example selects the same project-owned Student-t builder as the preferred form. Acquisition, filtering, basis construction, labelled input assembly, conversion of delayed arrays for PyMC, sampling, predictive selection, filenames, and output handling remain library-owned.

In a project created with the OpenGHG project cookiecutter, copy the preferred modules to src/<package_name>/likelihoods.py and src/<package_name>/run_with_likelihood.py. Copy the complete module below to src/<package_name>/rhime_runner.py only when the project needs to own a deeper orchestration change. Import scientific stage implementations from openghg_inversions.rhime rather than copying those implementations.

Run it with a normal RHIME configuration and optional overrides:

python -m package_name.rhime_runner config.ini \
    --start-date 2020-01-01 --end-date 2020-02-01 \
    --output-path outputs --draws 1000 --tune 1000 --chains 4

Less common Python/config options can be supplied as a JSON object:

python -m package_name.rhime_runner config.ini \
    --kwargs '{"reload_merged_data": true, "output_format": "inv_out"}'

The test suite imports all three sources, exercises both runners, and validates the likelihood contract directly, so the documentation and runnable examples cannot drift apart.

  2
  3This example deliberately replaces RHIME's default likelihood with a
  4project-owned Student-t builder. The orchestration is intentionally copied so
  5that a project can make deeper scientific changes while continuing to reuse
  6the supported acquisition, preparation, model, sampling, and output stages.

 42    *,

 46    """Run standard RHIME with a project-owned Student-t likelihood.
 47
 48    Args:
 49        config_file: Optional RHIME INI configuration file.
 50        **kwargs: Standard RHIME option names that override values from
 51            ``config_file``.
 52
 53    Returns:
 54        The sampled result and any outputs requested by the RHIME options.
 55
 56    Raises:
 57        TypeError: If the likelihood builder returns an invalid result type.
 58        ValueError: If required options are missing, aggregation or output is
 59            unsupported, or likelihood roles or metadata are invalid.
 60
 61    Notes:
 62        This workflow may retrieve or reload data, materializes related model
 63        arrays together at the named PyMC boundary without mutating canonical
 64        prepared inputs, runs sampling, and writes outputs requested by the
 65        resolved RHIME options.
 66    """
 67    params = (
 68        params_from_config(config_file, extra_kwargs=kwargs, normalise=False)
 69        if config_file is not None
 70        else dict(kwargs)
 71    )
 72    setup = resolve_rhime_options(params=params, multisector=False)
 73
 74    merged = retrieve_or_reload_rhime_data(setup.data_args, multisector=False)
 75    filtered = filter_rhime_observations(merged, setup.data_args)
 76    basis_functions = build_rhime_basis(filtered, setup.data_args)

 78        filtered,
 79        basis_functions,
 80        setup.data_args,
 81        multisector=False,
 82    )

 84    run_spec = with_prepared_rhime_sites(setup.run_spec, prepared)

 87        prepared,
 88        aggregation_error_mode=run_spec.model.aggregation_error_mode,
 89    )
 90    build_and_sample_start = perf_counter()
 91    model_build_result = build_standard_rhime_model(
 92        prepared=prepared,
 93        model_inputs=model_inputs,
 94        run_spec=run_spec,
 95        # This is the deliberate scientific replacement in the copied runner.
 96        likelihood_builder=likelihood_builder,
 97    )
 98    idata = sample_rhime_model(
 99        model_build_result,
100        setup.sampler,
101        use_variable_roles=True,
102    )
103
104    return make_standard_rhime_result(
105        prepared=prepared,
106        run_spec=run_spec,
107        sampler=setup.sampler,
108        model_build_result=model_build_result,
109        idata=idata,
110        build_and_sample_seconds=perf_counter() - build_and_sample_start,
111        likelihood_builder=likelihood_builder,
112    )

Compose a custom basis stage#

The second complete runner replaces one call in the preparation spine: build_project_basis replaces build_rhime_basis. The project function composes public basis primitives instead of selecting a built-in basis algorithm. It:

  • derives and normalises a two-dimensional weight field with basis_weights_from_fp_all;

  • loads the public country grid and reduces positive country codes to land and the remaining cells to ocean;

  • creates physical north-south/east-west coordinates with LatLonGridGeometry;

  • uses balanced inertial splits, decomposes every proposed child into four-neighbour connected components, and rejects splits whose children exceed the configured PCA eccentricity guard;

  • generates class-safe labels with region_constrained_basis; and

  • wraps the flat labels and current run flux in retained BasisFunctions with basis_functions_from_fp_all_flat_basis.

The nested split strategy follows the latest selected-country guarded-basis variant in the verification-games project. That variant gives the UK, Ireland, France, Germany, Italy, Belgium, and the Netherlands separate classes, while remaining land and ocean form two more. This smaller example deliberately uses the land/ocean class variant so the composition stays readable. To adopt the selected-country policy, replace _land_ocean_classes with a project function that maps the loaded integer country codes or country names to those classes. Keep this classification outside OpenGHG Inversions unless it becomes a broadly supported policy.

The weighting is deliberately not identical to that later verification-games preparation step. Verification-games sums absolute cached fp_x_flux after those sensitivities exist. At this earlier visible-runner basis boundary they have not been constructed yet, so the example uses the public basis_weights_from_fp_all field while preserving the guarded split strategy and class composition.

The flat labels and retained object record namespaced provenance for the class policy, normalised weight source, connected balanced-inertial strategy, connectivity, and eccentricity threshold. Those fields travel with a saved BasisFunctions artifact and make the project choice inspectable later.

Acquisition, filtering, sensitivity construction, labelled input assembly, the standard likelihood and model, conversion of delayed arrays for PyMC, sampling, predictive selection, filenames, and output handling remain library-owned.

The project owns the scientific validity of its classification, coverage, region count, eccentricity threshold, and split policy. BasisFunctions and the unchanged downstream stages validate the grid, coordinates, sources, site alignment, state layout, and model inputs they consume; they cannot certify that the project’s scientific partition is appropriate. Malformed artifacts fail while loading; structurally valid artifacts fail later if they violate a downstream alignment contract.

The example exposes project_basis_path separately from standard RHIME options. Point it at a self-contained .nc or .zarr artifact written by BasisFunctions.save to bypass fitting:

python -m package_name.custom_basis_runner config.ini \
    --project-basis-path cache/project-basis.zarr

The eccentricity guard is also a visible project-owned option, rather than an opaque library default. It defaults to 10 and is removed before standard RHIME option resolution:

python -m package_name.custom_basis_runner config.ini \
    --max-child-pca-eccentricity 10

BasisFunctions.load loads the saved operator, metadata, and flux into memory, then closes the artifact. The saved flux is deliberately retained. Use the standard public load_basis_functions helper instead when loading a named RHIME basis cache that should take its retained flux from the current fp_all acquisition.

Without an artifact, the basis-building function computes the arrays needed by the splitting algorithm. Before that point, the filtered xarray objects may still defer their calculations with Dask. The function derives and normalises the two-dimensional weights, loads the country classes, constructs the geometry, and creates the region labels. It then combines the labels with the current run’s flux in a BasisFunctions object. That object flows unchanged through sensitivity construction and labelled assembly. The arrays needed by PyMC are converted separately by materialize_pymc_inputs immediately before model construction.

The customisation is concentrated in _guarded_basis. The runner’s one deliberate substitution is marked by an inline comment where build_project_basis replaces the standard build_rhime_basis call. The complete source remains below because the test suite executes the same file that the documentation displays.

Copy examples/rhime_customisation/custom_basis_runner.py to src/<package_name>/custom_basis_runner.py and keep the project basis rule beside the copied orchestration spine. This source is imported and executed by integration tests and rendered here, so the documentation and runnable example cannot drift apart.

This guarded composition is intentionally project-specific and is not yet a common, stable strategy that warrants another lower-ceremony run_rhime option.

  1"""Run standard RHIME with project-owned emissions basis construction.
  2
  3This copy-and-modify example keeps RHIME's supported acquisition, filtering,
  4sensitivity, labelled-input, model, sampling, and output stages.  Only the
  5emissions-basis stage is replaced by :func:`build_project_basis`.  The example
  6either loads a self-contained retained ``BasisFunctions`` artifact or creates
  7a guarded region-constrained basis whose regions stay within land/ocean
  8classes, remain connected, and satisfy a project eccentricity threshold.
  9The verification-games workflow weights that strategy with summed absolute

 68def _land_ocean_classes(
 69    *,
 70    domain: str,
 71    country_directory: str | Path | None = None,
 72) -> xr.DataArray:
 73    """Reduce the public country grid to the project's land/ocean classes.
 74
 75    Args:
 76        domain: RHIME domain used to select the country grid.
 77        country_directory: Optional directory containing the domain country
 78            file.
 79
 80    Returns:
 81        An eager object-valued ``(lat, lon)`` class grid preserving the loaded
 82        coordinates. Positive country codes are ``land``; null, zero, and
 83        negative codes are ``ocean``.
 84
 85    Raises:
 86        FileNotFoundError: If the requested country grid does not exist.
 87        KeyError: If the country-grid artifact does not contain ``country``.
 88    """
 89    country_classes = load_country_region_classes(
 90        domain,
 91        country_directory,
 92    )
 93    return xr.where(country_classes > 0, "land", "ocean").astype(object).rename("basis_class")

 96def _guarded_basis(
 97    merged: RhimeMergedData,
 98    data_args: Mapping[str, Any],
 99    *,
100    max_child_pca_eccentricity: float,
101) -> BasisFunctions:
102    """Build the project's connected, eccentricity-guarded retained basis.
103
104    The public weight adapter intentionally materializes a derived 2-D weight
105    field from borrowed footprint and flux inputs here. The project then owns
106    normalization, class composition, guarded splitting, and conversion of the
107    flat labels to retained ``BasisFunctions`` without mutating ``merged``.
108
109    Args:
110        merged: Filtered, borrowed RHIME observations and flux data.
111        data_args: Resolved standard RHIME data and basis options. This stage
112            consumes required ``domain`` and optional ``flux_sources``,
113            ``nbasis``, and ``country_directory``.
114        max_child_pca_eccentricity: Project limit on each proposed child's
115            physical-coordinate PCA eccentricity.
116
117    Returns:
118        Retained basis functions fitted within connected land/ocean regions.
119
120    Raises:
121        FileNotFoundError: If the requested country grid does not exist.
122        KeyError: If ``domain`` or country-grid content is missing.
123        ValueError: If zero-filled weights do not have a positive finite
124            maximum, or geometry, allocation, or guarded splitting is invalid.
125    """
126    # 1. Turn the filtered footprints and flux into one spatial importance map.
127    weights = basis_weights_from_fp_all(
128        merged.fp_all,
129        data_args.get("flux_sources"),
130        abs_flux=True,
131    )
132    finite_weights = weights.fillna(0.0).astype(np.float64)
133    maximum = float(finite_weights.max())
134    if not np.isfinite(maximum) or maximum <= 0.0:
135        raise ValueError("Project basis weights must have a positive finite maximum.")
136    normalized_weights = finite_weights / maximum
137
138    # 2. Define scientific boundaries that no basis region may cross.
139    region_classes = _land_ocean_classes(
140        domain=data_args["domain"],
141        country_directory=data_args.get("country_directory"),
142    )
143    geometry = LatLonGridGeometry.from_dataarray(normalized_weights)
144    # 3. Compose the split algorithm and its shape/connectivity safeguards.
145    strategy = ConnectedComponentSplitStrategy(
146        split_strategy=GreedySplitStrategy(
147            split_step=ConnectedComponentPartitionStep(
148                split_step=InertialSplitStep(
149                    balanced=True,
150                    geometry=geometry,
151                ),
152                connectivity=1,
153            ),
154            split_acceptance=MaxChildPCAEccentricity(
155                max_child_pca_eccentricity=max_child_pca_eccentricity,
156                geometry=geometry,
157            ),
158        ),
159        connectivity=1,
160    )
161    # 4. Allocate and split regions within the land/ocean classes.
162    basis_flat = (
163        region_constrained_basis(
164            normalized_weights,
165            region_classes,
166            int(data_args.get("nbasis", 100)),
167            allocation="weight",
168            min_regions_per_class=1,
169            split_strategy=strategy,
170        )
171        .astype(np.int16)
172        .rename("basis")
173    )
174    provenance: dict[str, str | int | float] = {
175        "openghg_inversions:basis_artifact_source": "project-guarded",
176        "openghg_inversions:project_basis_strategy": "connected_component_balanced_inertial",
177        "openghg_inversions:project_basis_connectivity": 1,
178        "openghg_inversions:project_basis_max_child_pca_eccentricity": float(max_child_pca_eccentricity),
179        "openghg_inversions:project_basis_class_policy": "land_ocean",
180        "openghg_inversions:project_basis_weights": "basis_weights_from_fp_all_abs_flux_normalized",
181    }
182    basis_flat.attrs.update(provenance)
183    # 5. Attach the current flux so standard RHIME sensitivity code can use it.
184    return basis_functions_from_fp_all_flat_basis(
185        fp_all=merged.fp_all,
186        basis_flat=basis_flat,
187        metadata=provenance,
188    )

191def build_project_basis(
192    merged: RhimeMergedData,
193    data_args: Mapping[str, Any],
194    *,
195    project_basis_path: str | Path | None = None,
196    max_child_pca_eccentricity: float = DEFAULT_MAX_CHILD_PCA_ECCENTRICITY,
197) -> BasisFunctions:
198    """Return the project-selected retained emissions basis.
199
200    Args:
201        merged: Filtered, borrowed RHIME observations and flux data.
202        data_args: Resolved standard RHIME data and basis options.
203        project_basis_path: Optional ``.nc`` or ``.zarr`` artifact previously
204            written by :meth:`BasisFunctions.save`.  The artifact is
205            self-contained, so its serialized operator, metadata, and flux are
206            retained rather than replaced with flux from ``merged``.
207        max_child_pca_eccentricity: Project limit passed to the guarded split
208            policy when generating a basis. Defaults to ``10`` and is ignored
209            when ``project_basis_path`` is supplied.
210
211    Returns:
212        Loaded or newly fitted retained basis functions.
213
214    Raises:
215        OSError: If the requested artifact cannot be opened.
216        KeyError: If required artifact content or generated-basis options are
217            missing.
218        ValueError: If the artifact or generated-basis configuration is
219            invalid.
220
221    Notes:
222        Loading eagerly materializes the artifact so no open file handle is
223        retained.  Without a path, project basis fitting is the named eager
224        basis-generation boundary.
225    """
226    if project_basis_path is not None:
227        return BasisFunctions.load(project_basis_path)
228    return _guarded_basis(
229        merged,
230        data_args,
231        max_child_pca_eccentricity=max_child_pca_eccentricity,
232    )

235def run_custom_rhime(
236    *,
237    config_file: str | Path | None = None,
238    project_basis_path: str | Path | None = None,
239    max_child_pca_eccentricity: float | None = None,
240    **kwargs: Any,
241) -> RhimeResult:
242    """Run standard single-sector RHIME with a project-owned basis stage.
243
244    Args:
245        config_file: Optional RHIME INI configuration file.
246        project_basis_path: Optional self-contained ``BasisFunctions`` artifact
247            to use instead of fitting the project guarded basis.
248        max_child_pca_eccentricity: Optional project split-policy threshold.
249            When omitted, the merged config/keyword value is used, falling back
250            to ``10``. This option is removed before standard RHIME resolution.
251        **kwargs: Standard RHIME option names that override values from
252            ``config_file``.
253
254    Returns:
255        The sampled result and any outputs requested by the RHIME options.
256
257    Raises:
258        OSError: If configured artifact, input, or output I/O fails.
259        ValueError: If RHIME options, the custom basis, or prepared inputs are
260            invalid.
261
262    Notes:
263        This workflow may retrieve or reload data, may eagerly fit or load a
264        basis, eagerly materializes PyMC model inputs, runs sampling, and writes
265        outputs requested by the resolved RHIME options.
266    """
267    params = (
268        params_from_config(config_file, extra_kwargs=kwargs, normalise=False)
269        if config_file is not None
270        else dict(kwargs)
271    )
272    configured_project_basis_path = params.pop("project_basis_path", None)
273    if project_basis_path is None:
274        project_basis_path = configured_project_basis_path
275    configured_eccentricity = params.pop(
276        "max_child_pca_eccentricity",
277        DEFAULT_MAX_CHILD_PCA_ECCENTRICITY,
278    )
279    if max_child_pca_eccentricity is None:
280        max_child_pca_eccentricity = float(configured_eccentricity)
281    setup = resolve_rhime_options(params=params, multisector=False)
282
283    merged = retrieve_or_reload_rhime_data(setup.data_args, multisector=False)
284    filtered = filter_rhime_observations(merged, setup.data_args)
285
286    # CUSTOMISATION POINT: the standard runner calls build_rhime_basis here.
287    # This project function either loads a saved basis or composes the guarded
288    # basis-building tools above. Every stage after this call is standard RHIME.
289    basis_functions = build_project_basis(
290        filtered,
291        dict(setup.data_args),
292        project_basis_path=project_basis_path,
293        max_child_pca_eccentricity=max_child_pca_eccentricity,
294    )
295    site_data = build_rhime_sensitivities(
296        filtered,
297        basis_functions,
298        setup.data_args,
299        multisector=False,
300    )
301    prepared = assemble_rhime_inputs(filtered, basis_functions, site_data, setup.data_args)
302    run_spec = with_prepared_rhime_sites(setup.run_spec, prepared)
303
304    # Cross the explicit eager PyMC boundary without changing canonical inputs.
305    model_inputs = materialize_pymc_inputs(
306        prepared,
307        aggregation_error_mode=run_spec.model.aggregation_error_mode,
308    )
309    build_and_sample_start = perf_counter()
310    model_build_result = build_standard_rhime_model(
311        prepared=prepared,
312        model_inputs=model_inputs,
313        run_spec=run_spec,
314    )
315    idata = sample_rhime_model(model_build_result, setup.sampler)
316
317    return make_standard_rhime_result(
318        prepared=prepared,
319        run_spec=run_spec,
320        sampler=setup.sampler,
321        model_build_result=model_build_result,
322        idata=idata,
323        build_and_sample_seconds=perf_counter() - build_and_sample_start,
324    )

327def _json_object(value: str) -> dict[str, Any]:
328    """Parse one command-line JSON object containing additional RHIME options.
329
330    Args:
331        value: JSON text to parse.
332
333    Returns:
334        The decoded JSON object.
335
336    Raises:
337        argparse.ArgumentTypeError: If the text is invalid JSON or decodes to
338            a non-object value.
339    """
340    try:
341        parsed = json.loads(value)
342    except json.JSONDecodeError as exc:
343        raise argparse.ArgumentTypeError(f"invalid JSON: {exc.msg}") from exc
344    if not isinstance(parsed, dict):
345        raise argparse.ArgumentTypeError("--kwargs must decode to a JSON object")
346    return parsed

349def main(argv: Sequence[str] | None = None) -> RhimeResult:
350    """Parse command-line options and run the custom-basis RHIME workflow.
351
352    Args:
353        argv: Command-line tokens excluding the program name. ``None`` reads
354            tokens from :data:`sys.argv`.
355
356    Returns:
357        The RHIME result returned by :func:`run_custom_rhime`.
358
359    Raises:
360        SystemExit: If argument parsing fails or help is requested.
361
362    Notes:
363        Data access, eager basis and model materialization, sampling, and
364        requested output writes are delegated to :func:`run_custom_rhime`; its
365        exceptions propagate unchanged.
366    """
367    parser = argparse.ArgumentParser(description=__doc__)
368    parser.add_argument("config_file", nargs="?", type=Path, help="RHIME INI configuration file")
369    parser.add_argument(
370        "--project-basis-path",
371        type=Path,
372        help="self-contained BasisFunctions .nc or .zarr artifact",
373    )
374    parser.add_argument(
375        "--max-child-pca-eccentricity",
376        type=float,
377        help="project guarded-basis threshold (default: 10)",
378    )
379    parser.add_argument("--start-date")
380    parser.add_argument("--end-date")
381    parser.add_argument("--output-path", type=Path)
382    parser.add_argument("--output-name")
383    parser.add_argument("--draws", type=int)
384    parser.add_argument("--tune", type=int)
385    parser.add_argument("--chains", type=int)
386    parser.add_argument(
387        "--kwargs",
388        type=_json_object,
389        default={},
390        metavar="JSON",
391        help="additional standard RHIME options as a JSON object",
392    )
393    args = parser.parse_args(argv)
394
395    overrides = dict(args.kwargs)
396    for name in ("start_date", "end_date", "output_path", "output_name", "draws", "tune", "chains"):
397        value = getattr(args, name)
398        if value is not None:
399            overrides[name] = value
400    return run_custom_rhime(
401        config_file=args.config_file,
402        project_basis_path=args.project_basis_path,
403        max_child_pca_eccentricity=args.max_child_pca_eccentricity,
404        **overrides,
405    )

409    main()
