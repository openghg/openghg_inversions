Boundary-condition basis options are now one nested `bc_basis` group (`BcBasisOptions` at `DataConfig.bc_basis`) with `paths`, `algorithm` and `split_height` fields. Python requests and JSON parameter files should pass `bc_basis={"algorithm": ...}`. Flat `bc_basis_paths`, `bc_basis_algorithm` and `bc_basis_split_height` names still work there with a `DeprecationWarning`. Standard and multisector preparation manifests write the nested layout as version 3 and continue to read version 2. INI files use the flat spelling. Python callers read `config.data.bc_basis.paths`, `.algorithm` and `.split_height`.
