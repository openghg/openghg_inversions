Boundary-condition basis options are now one nested `bc_basis` group (`BcBasisOptions` at `DataConfig.bc_basis`) with `paths`, `algorithm` and `split_height` fields. Python requests and JSON parameter files should pass `bc_basis={"algorithm": ...}`; flat `bc_basis_paths`, `bc_basis_algorithm` and `bc_basis_split_height` names still work there but emit a `DeprecationWarning`. Saved preparation manifests now record `data.bc_basis` as a nested mapping; older manifests with flat names still load, with the same warning. INI files keep the flat spelling unchanged. In Python, read `config.data.bc_basis.paths` (and `.algorithm`, `.split_height`) instead of the former flat attributes.
