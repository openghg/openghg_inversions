Linked CO2/O2 configuration, handoffs and outputs accept CO2 in ppm with O2 as per-meg δ(O2/N2) when the prepared artifact declares that observable. The declaration (`openghg_inversions.inversion_data.o2n2.DeltaO2N2Declaration`, stored in preparation provenance under `o2_observable`) records the reference O2/N2 ratio and its source; configure it with `channels.o2.observable = "delta_o2_n2"`. The new `validate_co2_o2_channel_units` checks each channel against its observable, and undeclared per-meg labels are still rejected because unit parsers read `"per meg"` as 1e-6 mol/mol. Basic products label each channel's `units` and `observable`, and the δ channel also records its reference ratio. PARIS products keep CO2 concentrations and any requested fluxes, but skip the δ(O2/N2) concentration product, because the v04 template holds dry-air mole fractions. The shared mole-fraction parser (`inversion_data._units.mole_fraction_unit_scale`) now rejects ratio-anomaly labels (per meg, per mil, per mille, ‰, ‱ and delta labels) before OpenGHG's unit registry can read them as 1e-6 or 1e-3, so surface preparation, merged-data checks, boundary conversion and PARIS reporting refuse them too. The public linked output helpers (`reconstruct_co2_o2_concentrations`, `make_co2_o2_paris_outputs`) now run the same per-channel unit and observable check as the configured path, so a δ(O2/N2) declaration on ppm O2 rows is rejected instead of relabelling them and silently dropping the O2 concentration product. Direct reporting still converts each mole-fraction channel with its own scale (for example ppm CO2 with ppb O2); identical mole-fraction labels remain required at the configured and handoff boundaries. `prepare_co2_o2_inputs` validates a δ(O2/N2) declaration and checks it against `o2_units` when the artifact is built. The declaration can also arrive as attributes on the O2 observations (`observable = "delta_o2_n2"` plus `delta_o2_n2_reference_ratio`, `delta_o2_n2_reference_ratio_source` and optional `delta_o2_n2_n2_policy` and `delta_o2_n2_scale`); preparation stores it in provenance. It can record the observations' calibration scale, and a missing reference ratio is an error rather than a default.
