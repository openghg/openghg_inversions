Remove the HBMCMC likelihood/prior compatibility switches and chain-0-only derived-output policy from RHIME construction and execution. Affected historical configurations receive guidance at the HBMCMC boundary to use OpenGHG Inversions 0.7. Version 0.8 outputs use all retained chains, including legacy-format summaries.

Remove the Python `run_rhime` API in 0.8 with import guidance to `run_standard`; the `run-rhime` CLI command keeps its files, logging and export defaults. Standard full, prepared-input and saved postprocessing return `InversionOutput`, including for no-output requests. Replace the three standard builders with eager `build_standard_model` and explicit `materialize_standard_inputs`. Remove `RHIME_PREPARATION_OPTION_NAMES`; use named configuration owners. New configuration helpers are `load_params`, `group_params` and `option_groups`.

Public `load_preparation` returns the prepared inputs, data configuration and generation identifier; external `save_samples` callers must pass that generation. Standard `basic` output requests no longer compute an inaccessible summary; call `basic_output` on the returned scientific result explicitly.

`RhimeModelBuildResult` now takes `model` and `output_contract`; move the former role, format and metadata arguments into `OutputContract`. Replace the removed standard result facade `make_standard_rhime_result` with `make_rhime_output(..., split_by_sectors=False)`.

Copied standard runners must call `postprocess_standard_outputs` for PARIS/legacy products before the export-only `save_inversion_output`, and validate destinations with `validate_standard_output_resources`. `acquire_merged_data` now only acquires data; replace the removed `standard.prepare_inputs` convenience function with explicit acquisition or supplied-data validation followed by `prepare_standard`.
